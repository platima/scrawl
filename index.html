Scrawl

7.9 KB gzipped · no deps

It draws wobbly SVG strokes behind your text, one per line box, so wrapping just works. Every stroke is seeded from the text itself, so it looks hand drawn but never changes between reloads. Eleven shapes, arrows, no dependencies, and it respects reduced motion.

Every marketing site wants the pen-on-paper underline and every one of them builds it again from scratch. This is that effect on its own, MIT, with no site builder attached. There is also a no JavaScript version if you only need static strokes, and the source is on GitHub.

wrapping

    
Across line breaks

    
Strokes are measured per line box, so a run that wraps gets one stroke per line rather than a single stroke stretched across the gap. Resize the window and they redraw.

    

      The hard part was never the drawing, it was
      working out where the text actually sits once the browser has finished laying it out,
      because a span that wraps is not one rectangle, it is several, and
      the naive approach draws one enormous stroke through the middle of your paragraph
      which nobody wants.
    

  


  


  

    
arrows

    
From here to there

    

      Point an arrow at another element with data-scrawl-to and it leaves the
      middle of one facing side and lands square on the other. Side by side it runs across, stacked it runs
      down, and it redraws when the layout changes. Stack these and watch.

install

    
Use it


    
Drop the script in, add a data-scrawl attribute, done. It self initialises on DOM ready.



<script src="scrawl.js"></script>

<p>Kept the good bits, threw out
  <span data-scrawl="scribble" data-scrawl-color="#d2372a">the busy parts</span>.
</p>


    
Or drive it from script:



Scrawl.annotate('#headline', {
  type: 'circle',
  color: '#1f8a5b',
  thickness: 3,
  animate: true
}).show();

Worth knowing

    

      The SVG is appended to the annotated element's parent at z-index: -1, and the parent
      gets position: relative and isolation: isolate if it did not have them. That
      keeps everything aligned through scrolling and scaled ancestors without any coordinate maths, and the
      isolation stops the negative z-index escaping to the root stacking context. If the annotated element
      itself has a background, or a later sibling paints over the stroke, you will want
      data-scrawl-front="true" instead. Redraws are debounced through a
      ResizeObserver on the parent plus document.fonts.ready, so a late web font
      does not leave strokes stranded under the old metrics.
    

    

      An arrow's SVG goes in the nearest ancestor holding both ends instead, and it also redraws when
      either end changes size. If that ancestor is something big, like <body>, making it
      relative can move anything absolutely positioned against an element further up, so name a closer one
      with data-scrawl-within.
